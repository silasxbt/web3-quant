# 版本规范

Future Quant 使用语义化版本规范：

```text
MAJOR.MINOR.PATCH
```

当前版本：

```text
0.1.0
```

## 版本含义

- `MAJOR`：不兼容的架构、配置、交易接口或数据结构变化。
- `MINOR`：新增功能，保持已有主要接口兼容。
- `PATCH`：缺陷修复、文档修正、轻量配置调整。

在 `1.0.0` 之前，项目仍处于实验和快速迭代阶段，`MINOR` 版本也可能包含较大的行为变化。涉及真实交易、API 密钥、下单执行、仓位对账和风控阈值的变化，必须在 `CHANGELOG.md` 中明确说明。

## 发布节奏

- `0.1.x`：行情监控、中文控制台、Telegram/macOS 提醒、本地启动链路。
- `0.2.x`：测试盘签名客户端、测试盘下单、撤单和仓位对账。
- `0.3.x`：双边执行器、单边成交补偿、测试盘全链路自动开平仓。
- `0.4.x`：生产盘只读影子运行、小额灰度准备。
- `1.0.0`：生产盘功能、风控、日志、配置和恢复链路达到稳定基线。

## 发布检查

每次发布前必须至少执行：

```bash
cargo fmt --all
cargo check
cargo test
cargo build
zsh -n FutureQuant.command scripts/*.sh scripts/*.command
```

如果涉及 Web 控制台，还需要用浏览器确认页面非空、中文显示正常、模块说明正常、API 状态正常。

如果涉及交易执行，还需要额外提供测试盘下单、撤单、仓位查询、异常补偿和 kill switch 验证记录。
